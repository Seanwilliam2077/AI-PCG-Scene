一句话：语义走模型，几何走算法

模型很会说「这是什么」，很不会说「有多大、在哪里」。
所以：语义（类别、支撑关系、文字内容、材质倾向）交给模型； 几何（尺度、位置、姿态）交给确定性算法； 模型给出的几何量只能当提示（hint），永远不许进主干 —— 拿不到它，整条管线也必须照样出结果。

这条线不是审美选择，是被三次实测逼出来的。同一份「模型报的尺寸」在本仓库里的表现：

  • 资产库 39 个模块。最长边之比（实测 ÷ 估计） 跨 0.51× 到 9.85×；换成注册表实际用的判据 —— 两组尺寸各自排序后逐轴取最大偏差倍数 —— 跨 1.21× 到 13.04×，其中超过 2 倍的正好 25 个， 全部进人工队列。（两个量不是一回事：前者可以小于 1， 后者按构造恒 ≥ 1。散点图画的是前者，needs_review 用的是后者。）
  • 用「模型给的标签」查已知高度表、再套在「模型给的框」上反解相机高， 两层误差叠加，多个先验物彼此矛盾到 MAD/median = 0.35 —— 同一张照片解出的机位高度散了三成。
  • 模型的九自由度三维盒（box_3d）在本管线里只做 yaw 的交叉证据： resolve_yaw 的优先级是 box_3d → 贴墙法线 → 随支撑物 → 长轴贴墙 → 面向相机， 拿不到第一项时后四条照常给出可用朝向。

反过来，模型在语义上的表现好到没有替代品：开放词表的对象清单、 attached_to 支撑关系、海报上的文字内容、屏幕内容的语义描述 —— 这些用规则写要写到天荒地老。分工，而不是二选一。

下文会在三个部分各回扣一次这条主线： 第一部分是「让模型只答语义」的提问结构，第二部分是「几何字段的所有权归测量」， 第三部分是「位姿全部由代数解出来、模型一个字都不参与」。

第一部分

图像的识别与分割

先说它怎么坏，再说怎么做

最贵的假设是「问一次就够了」。强视觉模型在整图上倾向把同类实例合并成一排： pipeline/stages/s01_perceive.py 里留着的实测记录是 16 台显示器只框出 13 个。这不是措辞问题 —— 提示词里已经写死了「一个可见实例一条，五台显示器就是五条」， 它依然合并。因为在整图被降采样后的分辨率上，那一排在模型眼里本来就是一个东西。

单遍检测天然欠召回，调提示词补不回来。 本仓库那张 1024×572 参考图，最终 70 个框里整图那一遍只贡献 21 个； 最终有 13 个 CRT 显示器框，整图一遍只给出 3 个。 剩下的都是后面三条召回补的。

方法：两段式提问 + 三条独立召回 + 保守合并

① 先解析场景，再检测。第一次调用问的是「这张图里有什么」， 返回对象清单、灯光、色板、支撑关系、文字内容；从中抽出 detection_phrase 拼成一份属于这张图的开放词表， 再连同固定的 floor / wall / ceiling 一起塞进检测提示词。 检测器拿到的不是一张固定类别表，而是这张图自己的名词列表。 这是「语义走模型」的第一处落地：模型的活是命名，不是测量。

② 三条召回复用同一份检测提示词，只换 crop。 三遍问的是同一个问题，变的只有喂进去的画面：

召回怎么裁 补的是什么本次贡献
整图原图（长边 < 1600 时先 ×2 上采样） 主干与大件21
语义热区 大件家具（table / desk / shelf / counter / cabinet）的框， 左右各外扩 4%、上方 10%、下方 4%，按面积取前 2 块，按原分辨率重检 桌面上的键盘、鼠标、杯子这类小件28

三条补召回合计 49 个，占最终 70 个框的 70%。 下面那个探针可以逐个看它们分别是什么。

③ 让分块可用的那一条规则：分清「接缝」和「图边」。 这是整段里最容易漏、漏了就白做的一条。分块检测会产出两种贴边的框， 它们必须被反着处理：

  • 碰到人工切缝的框 → 丢弃。跨块物体在每一块里都只露半截， 半截框与整图框的 IoU 不够高，过不了 NMS，最后变成幽灵复制品。
  • 碰到真实图边的框 → 保留。沿墙的桌带、贴着画幅左缘的椅子， 本来就延伸出画面。一刀切会把参考图的定义性结构整条删掉 —— 实测踩过。

判定只需要知道这条边是不是原图的边：块的左边界 > 0.001 说明它是切出来的， 框贴上去就是切缝；块的左边界 = 0 说明它就是图的左缘，框贴上去是真出画。 容差用 2% 的带宽。

edge = 0.02
cut_l = bx[0] < edge and cx0 > 0.001      # 贴到人工切缝 → 丢
cut_r = bx[2] > 1 - edge and cx1 < 0.999  # 同理
# cx0 == 0 / cx1 == 1 时上面两条都不成立 → 贴的是真实图边，保留
这条规则成立有三个前提，缺一条就变成净删除。
  1. 裁块必须是原图坐标系里的轴对齐矩形，且不带 letterbox 填充。 上面那个判据是拿「块的归一化边界」和 0 / 1 比大小， 换成旋转框、掩膜引导的不规则 crop、或透视矫正后的四边形， cx0 > 0.001 这个标量根本不存在。 一般形式应该写成：逐条枚举 crop 的边界，问「这条边是不是原画幅边界的子集」， 是则贴它的框保留，否则丢。检测器要求方形输入而做了补边时更要小心 —— 补出来的边既不是切缝也不是图边，贴上去的框是纯粹的伪影， 而按上面的写法它会被当成「真实图边」留下来。
  2. 重叠带必须宽于你预期会跨缝的最大物体。 丢掉半截框之所以安全，唯一的理由是这件东西在邻块里还会被完整地看到一次。 本管线的重叠是 0.2 图宽，比画面里任何一件家具都宽，所以成立。 重叠不够时，这条规则就是在无声地删物体，而且没有第二次机会。 换项目时先量一遍：重叠带 ≥ 最大物体的画面宽度，否则先加重叠再谈这条规则。
  3. 「碰真实图边就保留」保的是框，不是框的尺寸。 它本来就延伸出画面，所以它的宽高是下界而不是测量值。 必须一路带一个「被画幅裁断」的标记下去：本管线里它进置信度（权重 0.25）， 并且把该实例从相机高反解与全局尺度校准里剔除。 只保留、不标记，等于把一个残缺框当完整框用。

④ 枚举只在证据充分时替换父框。先把面积 ≥ 父框 80% 的子框逐个剔掉 （那是模型把父框原样抄了一遍）；剩下的子框还有 ≥ 2 个时，才用这一组替换父框， 否则原样保留父框，一件也不发明。枚举调用失败同样保留父框。 注意是「过滤后仍 ≥ 2」而不是「所有子框都必须小于 80%」—— 一个超大子框只会被丢掉，不会一票否决整次拆分。 这条约束的作用是让「拆分」永远不会变成「幻觉」。

⑤ 小图先 ×2 上采样。检测坐标是归一化的，放大送入不需要任何坐标换算 —— 纯赚细节。本管线的阈值是长边 < 1600 就先双三次放大一倍。

⑥ 坐标序陷阱，一次吸收干净。同一个模型 框返回 (y, x) 序、掩膜多边形返回 (x, y) 序，两者相反，且都归一化到 0–1000。 这种事必须在归一化层一次性转成下游统一消费的标准形（xyxy + (x,y)，均 0~1）， 不能让每个消费方各自记得。同一层顺手丢掉退化框（宽或高 < 1e-3）。

结构可靠性是本地契约，不是接口特性

不要指望「返回严格 JSON」这件事由服务端保证。可迁移的做法是把它做成一条本地降级梯：

去 ```json 围栏  →  json.loads  →  括号配平扫描（带字符串/转义状态机）
              →  调用方传入的 validator（缺字段就抛）
              →  失败则把解析错误原文回抛给模型，只做 一次 修复重试
              →  修好的文本 写回原缓存槽 ，此后重放免费且字节一致

括号配平扫描是关键的中间档：模型经常在 JSON 前后加一句解释， 为一句废话重跑一次调用既慢又贵。扫描时必须跟踪字符串与转义状态， 否则字符串里的 } 会提前收尾。

缓存键 = hash(模型, 参数, 提示词, 图像字节)。 端点刻意不进键 —— 换网关地址不该让整个缓存失效， 而且调用留痕落盘时也不该把内部地址带出去。缓存目录随交付归档， 评审机没有网络权限时可以整条离线重放；缓存未命中时显式报错， 绝不静默降级成「跳过这一步」。

诚实：这套方法本身的三个已知弱点（都出自本仓库，都还没修）
  • 受控词表只注入了资产打标提示词，没注入感知提示词。 资产库注册时把 categories 列表格式化进提示词里，模型只能从表里选； 而感知阶段发的是自由文本，事后才靠 normalize_category 归一。 两头对齐会省掉一整层歧义。
  • NMS 按小写标签精确相等匹配，而分块会返回带实例后缀的标签。 本次运行 70 条里有 6 条形如 beige crt monitor 2、 white folding table 1 —— 它们与 beige crt monitor 在 NMS 眼里是两个类， 永远不会互相抑制。正确做法是先过类别归一再比较。
  • NMS 的优先级实际退化成了插入顺序。 检测提示词根本没要 score，枚举提示词要了 confidence 但归一化层只读 score 字段、把它丢了； 于是 sorted(dets, key=-score) 面对一堆 1.0 变成稳定排序 = 插入顺序 = 整图 → 热区 → 分块 → 枚举。 这个顺序碰巧是合理的（先信大图、后信局部），但它是意外，不是设计。

第二部分

对应资产的生成

先定选型判据

两条路不是替代关系，判据在下面这张表里。先看最后一行 —— 失败形态的差别比成本差别重要得多。

1 · 离线预处理是必修课，不是优化项

云端图生 3D 的产物不能直接进引擎。本仓库的预处理链（作者侧一次性执行， 评审机不需要）：

  • QEM 减面，且必须保 UV —— 用带纹理坐标保持的二次误差边坍缩滤镜 减到约 8 万面。不保 UV 的减面会把贴图撕碎，等于白减。
  • 贴图降档 —— 基础色 4096→2048 存 JPG（无损保留源字节的资产格式里， JPG 源比 PNG 小 5 倍，这是交付体积预算的关键）；法线 1024 PNG。
  • ORM 合并 —— metallic + roughness 合成一张 R=AO(恒白) / G=Roughness / B=Metallic 的 1024 PNG， 通道约定与母材质一致。三张图变一张。
  • 坐标系归一 —— Y-up 米 → Z-up 厘米（绕 X 转 +90、×100）， 枢轴统一到底面中心。这一步的产物同时写出 stats.json：变换后包围盒（cm）、面数、文件清单。 它是后面所有几何判断的底数。

2 · 字段所有权切分 —— 这条最值得直接抄走

语义字段来自模型，但一旦人核对过就冻结，重跑打标不覆盖。
几何字段永远从实测重写：人不改，模型不碰。

落地形态很小：注册表条目上挂一个 human_verified 布尔；为真时 整条语义部分（类别、是否屏幕、是否平面印刷、估计尺寸、打标置信度）原样保留， 而 mesh_bbox_cm / tri_count / pivot / 文件路径这一组无条件从 stats.json 覆盖。

模型的估计尺寸不参与任何缩放，只用来做交叉校验： 与实测包围盒的最大轴向偏差 > 2 倍、或类别落到 misc、 或打标置信度 < 0.5，就打上 needs_review 进人工队列。 本仓库 39 个模块里 25 个被打上了这个标。

3 · 四级瀑布

  1. 人工覆盖（按实例 id）—— 无条件采纳，人说了算。
  2. 精确类别命中 —— 同类多个变体按尺度无关的形状距离排序后轮换分配。 形状距离 = 三轴长度各自排序后比值取对数的绝对值之和： Σ|log(a_i / b_i)|。取对数使它对整体缩放不敏感 —— 它只问「形状像不像」，把「多大」留给后面的缩放去解决。 轮换游标按实例 id 排序推进，所以复跑字节一致。
  3. 视觉兜底 —— 参考图 crop 对候选预览拼图，置信度达标才采纳。
  4. 降级 proxy 盒 —— 尺寸永远正确，场景比例不塌。

本次运行 30 个对象：精确类别命中 21、降级 proxy 9； 带标志的 17 个（SHAPE_MISMATCH 8、SCALE_CLAMPED 3、NO_MATCH 9）。

4 · 畸形缩放保护：四档，而且刻意不对称

  • 取三轴比的中位数做统一缩放。中位数抗单轴离群，又保住外形比例； 取平均会被一根跑飞的轴带走。
  • > 10× 或 < 0.1× → 判定误匹配，不落地这个畸形网格， 直接推进到下一个候选。
  • 放大钳在 1.7×。前提是库资产按真实尺寸建模；此时布局把一张桌子 解算成 4.6 m，多半是深度高估而不是真有巨桌 —— 宁可信资产，不信解算器。 实测那张近景巨桌就是 2.58× 惹的祸。
  • 缩小方向不钳。小物件确实存在，这个方向没有对称的理由。
  • 屏幕类强制 x/y 同比（取两轴比的均值），4:3 的显像管不许被拉成宽屏； 剩下两档 SCALE_DANGER / SCALE_WARN （出 [0.2,5] / 出 [0.5,2]）只报不改，供下游追溯。 另外三轴比的极差 > 3 倍时打 SHAPE_MISMATCH —— 那是拿主机塔去配长桌的形态。
照抄这四个阈值之前，先问一句：你的库是米制的吗？
这四个数全都是「库网格已经是真实尺寸」这个前提的产物， 而图生 3D 的输出恰恰不满足这个前提 —— 本页下面那张散点图就是证据： 本仓库 39 个模块的实测最长边全部落在 75–118 cm，与它是鼠标还是长桌无关。 于是 size_cm / mesh_bbox_cm 算出来的不是「该放大多少」， 而是「这件东西的真实尺寸相对 1 m 是多少」，四档保护随之全部错位：
  • 1.7× 钳制反过来制造误差。实测本次运行 white_folding_table_08 → M15 与 white_folding_table_32 → A03 都被钳到 [1.7, 1.7, 1.7]：M15 的网格最长边 91.5 cm， 折叠桌真长 183 cm，正确比值就是 2.0 —— 钳完只剩 155 cm，短了 15%，而且这 15% 是钳制自己造的。
  • 10×/0.1× 拒收带编码的是库的尺寸分布，不是物理。 归一化到 ~1 m 的库里，任何真实尺寸小于 10 cm 或大于 10 m 的物体 都会仅仅因为归一化而被判「误匹配」。
  • SHAPE_MISMATCH 会常态化。本次 21 个库匹配里 8 个带这个标志 （6 个主机塔全中、2 张长桌全中）—— 阈值 3× 是对「两个真实尺寸的盒子」 调的，拿去比「真实盒 vs 归一化盒」必然虚报。
正确的做法：把「归一化 → 真实尺寸」当成预处理的一步补上 （用人工核对过的 est_size_cm、或按类别的先验高度把每个模块先缩到位， 写回 mesh_bbox_cm），然后再套这四档。 做不到的话，就把阈值从你自己这个库的比值分布里定出来， 或者干脆关掉放大钳 —— 但不要照抄 1.7。

5 · 两个类别必须禁止进库匹配

misc —— 「未知配未知」。实测把一根结构柱配成了大理石杂物盒。
cable（含 pipe / conduit）—— 细长物配上线缆盘资产， 20 个实例沿墙一摆就是一面蓝色假墙。
两者的归宿就是细长 proxy 盒 —— 反而更像管线。这两类连视觉兜底都不进。

6 · 平面印刷品走贴花，且贴花源不能是基础色贴图

海报、告示、报纸不做网格匹配，走贴花路径。但贴花的图必须取 白底完整预览渲染，不能取 T_BC —— 库里的平面印刷品是「皱纸」三维模型，它的基础色贴图是碎片化的 UV 图集， 贴上墙是一块马赛克。实测翻过车。

同一张海报优先回到原位（按文字重合度选）， 多实例的海报组再从全量贴图池里轮换 —— 一面「贴满各式海报」的墙，同一张贴 15 遍会假。

7 · 注册表不可信，测量才是裁判

同一个「这东西多大」，在本管线里前后换过三个信息源， 每一次替换都是被一次肉眼可见的失败逼出来的：

尺寸来源用在哪为什么被下一个取代
① 布局意图尺寸解算器输出的期望外形 它是「应该多大」，不是「网格实际多大」
② 库网格包围盒 × 缩放装配时的模型级吸附与去穿插 模型高度与库网格真实高度仍有落差 —— 矮桌变体实测顶面比模型低 35 cm，桌上的东西整批悬空
③ 引擎实测 bounds终局重力吸附与穿模检测 —— 它就是裁判。底面落到脚印重叠 ≥ 30% 的最高支撑面顶，两轮迭代让叠放物连锁下落
规律：任何写在配置里的几何量，都会在某一步被现实推翻一次。 与其争论哪个源更准，不如把「最后一步用实测重量一遍」写进流程。

1 · 一份数据，两处消费

总平面（院落网格：每个院子带用途、种子、LOD、有没有场坪、四面墙的开口） 是唯一数据源，地面烘焙和三维摆放读同一份。 于是混凝土场坪的边界永远和院墙严丝合缝 —— 不是对齐出来的，是构造上不可能不齐。 两套数据各自生成再对齐，是这类场景最常见的返工来源。

2 · 反照率推近白，颜色放进顶点色

程序化混凝土贴图的基准亮度写死在 0.80， 噪声只在其上下摆动；真正的颜色由每个构件发射时写进顶点色。 于是同一张混凝土贴图可以同时当墙、路面、掩体、路缘石， 颜色变化不需要拆材质。这是把几十种材质压缩到十几个桶的前提。

配套的一条：UV 按世界尺寸重排（把盒子每个面的 UV 按米缩放）， 所以 3 m 的墙和 30 m 的楼纹理密度一致，不会一个糊一个碎。

3 · 平铺性是构造出来的，不是修出来的

值噪声的格点坐标按周期取模后再插值：

const x0 = ((xi % p) + p) % p, x1 = (x0 + 1) % p;
const y0 = ((yi % p) + p) % p, y1 = (y0 + 1) % p;

右边缘的格点与左边缘是同一个格点，无缝就成了数学保证。 多倍频叠加时每一层各自按自己的频率取模，仍然无缝。 对比之下，「生成完再镜像/羽化接缝」永远是在补救。

4 · 每格自带种子

总平面给每个院落存一个自己的整数种子，构件生成时用它起一条独立的随机流。 结果是生成与顺序无关、局部稳定：改一个院子不会让别的院子跟着重排， 也可以只重算画面里的那几格。共享一条全局随机流的写法在第一次「只想改一处」时就会暴露。

换种子重排的只有「随机填充」的那 88 个院落， 手工排的前三排、周界与道路网格不动 —— 换 seed 是另一座基地，不是另一堆噪声。

5 · 按材质桶合并

所有静态构件在同一个变换栈里就地生成，直接吐世界坐标的几何，按材质丢进桶里， 最后每桶 merge 成一个 Mesh。发射时要做四件事，缺一件合并就会失败或变胖：

  1. 把变换烘进几何（applyMatrix4），此后没有独立变换需要维护；
  2. 只保留 position / normal / uv / color 四个属性并删掉其余 —— 属性集必须完全一致才能合并；
  3. 非索引几何（挤出体、多面体）补一条平凡索引 —— 合并要求「要么全有 index，要么全没有」，补索引比把其它几何全展开省一半以上顶点；
  4. 清掉几何分组。

本仓库那一局：44 897 个构件、170 万顶点 （归档源码实跑值；当时出图那一版记录的是 44 441，差 1%）， 合并成 12 个构筑物 Mesh + 2 层地面 = 14 个网格。 声明了 13 个材质桶，实跑用上 12 个（有一个桶从未被填过，运行时就不生成对应 Mesh）。

6 · LOD 做在生成层，不是换网格

不要先生成全细节再换低模。按离相机的排数在发射构件时就少发： dist ≥ 4 → LOD 2、dist ≥ 2 → LOD 1、其余 0。 最远那批里，一整段 T 形院墙退化成一个盒子，省掉九成构件。 本仓库 121 个院落的分布是 22 / 22 / 77。

这样做的收益不只是绘制，更是生成时间与内存 —— 低细节的那部分几何从来没有存在过。

7 · 接触阴影用顶点色近似

没有实时 GI 时，最便宜的「坐得住」是按世界高度把顶点色压暗一档：

f = 1 - aoS * (1 - clamp(y / aoH, 0, 1))
// 本仓库取 aoH = 1.6 m, aoS = 0.24：1.6 m 以下最多压暗 24%

它不是 AO，它只是一条随高度的渐变，但它落在物体与地面的接触处， 而那正是「浮不浮」的全部信息所在。任何整图平均亮度类的指标都看不见它 —— 实测开关屏幕空间 AO 前后整图平均亮度只差 0.021 档， 但被压暗的那 12.9% 像素全在接触面上。

交互 · 尺寸可信度散点

39 个资产模块，横轴是模型估计的最长边（对数轴）， 纵轴是网格实测包围盒最长边。点图例可以开关分组，点上方按钮按类别筛选， 鼠标移到表格行上会高亮对应点。

要看的就一件事：所有点都挤在一条横带里。 实测最长边全部落在 75.0 – 117.8 cm， 与它到底是鼠标、易拉罐还是长桌完全无关 —— 图生 3D 的输出是归一化的，不是米制的。 定义 比值 = 实测最长边 / 估计最长边，它跨 0.51 到 9.85，19 倍。 这就是为什么只有实测包围盒可以参与缩放。

读表提示：「比值」列和「标记」列用的不是同一个量。 比值列是最长边之比（图上那个点的纵横坐标之比），红绿只是按 >2 / <0.5 上色； needs_review 用的是注册表的判据 —— 两组尺寸各自排序后逐轴 取最大偏差倍数 > 2（或类别为 misc、或打标置信度 < 0.5）。 所以会出现「比值 1.94 是绿的、却带 needs_review」这种行（M02、M06、M40、M34、M29、M37、M24）， 那不是标错了，是逐轴看比只看最长边更严。

第三部分 · 只讲方法

DCC 里的相机还原与位姿估计

这一节刻意不引用本项目的实验数值（还原度、房间尺寸、逐物体配准都在另外几篇里）。 下面只有换个项目照样成立的部分。

共同骨架就三行代数

像素 (u,v)  →  射线 d = R · K⁻¹ · [u, v, 1]ᵀ
射线 ∩ 声明的支撑平面  →  世界点
    地面   z = 0     t = h / (−d_z)        需 d_z < 0（底边在地平线下方）
    支撑面 z = z_s   t = (z_s − h) / d_z   先解出支撑物才有 z_s
    天花板 z = H     t = (H − h) / d_z     需 d_z > 0
    墙面 n·P = c     t = (c − n·C) / (n·d) 取 t > 0 的最近墙

用 Blender、UE 还是别的，这三行代数不变。变的是它两端的搬运层 —— 而搬运层比「手性 + 单位」多得多。不要让每个消费方各自记得， 把下面六件事收进一个转换函数：

要换的东西本仓库怎么换的 抄漏了会怎样
手性右手 FLU → UE 左手：Y 取负， yaw 同步取负 整场镜像。单帧里看不出来，只是所有东西「反了」
单位米 → 厘米即 ×100 只有在 DCC 处于默认单位刻度时才对（UE 的 WorldToMeters、 Blender 的 unit_scale_length 都能改掉它）
上轴Y-up → Z-up：绕 X 转 +90 这一条不由手性推出来。glTF/three.js 是 Y-up，UE/Blender 是 Z-up， 四种组合都存在
枢轴预处理阶段统一归到底面中心 整批物体按各自的建模原点落位。本仓库还额外用引擎实测 bounds 做终局重力吸附 —— 因为模型级枢轴和真实网格仍差到 35 cm
欧拉序 / 旋转正方向 物体只输出 yaw，相机的 pitch/roll 单独走标定 Blender 默认 XYZ、本仓库程序化侧用 'YXZ'、 UE 是 pitch/yaw/roll 且左手正方向 —— 三者两两不同。 只翻 yaw 的符号在有 pitch 的相机上会立刻穿帮
FOV 沿哪根轴输出里 hfov_deg 与 vfov_deg 都写 本仓库自己就踩在两边：cameras.json 给的是水平 FOV， 而程序化那条线用的 THREE.PerspectiveCamera(30, …) 第一个参数是垂直 FOV。把 hfov 直接喂进去，16:9 画幅上就是一台错的相机

另有一条容易漏的：主点偏移的表示法各家不同 —— 本仓库 recon/core/cam.py 用的是 Blender 的 shift_x/shift_y 约定（两个方向都按画幅宽归一化，且 y 取负）， UE 根本不这么表达。所以本节最后那条「点阵双向投影」不是锦上添花， 它就是这张表的验收测试 —— 六件事里错任何一件，点阵都会报出来， 而任何单帧渲染都看不出来。

因此求解必须分层：先地面物 → 定房间盒 → 再桌面物 → 再墙/顶物。 层级由感知层给出的 attached_to 声明，据此做拓扑排序。 环依赖（模型偶尔会互标）直接降级为落地物处理，不让整批卡死。

消失点求解：几个工程要点

  • 先 CLAHE 再检线段。低照度参考图上直接检线段会大面积漏检。
  • LSD 要带 Hough 回退。它在 OpenCV 3.4.6–3.4.15 与 4.1.0–4.5.3 因原实现许可证冲突被移除 （不是专利问题），4.5.4 起以 MIT 授权实现恢复。落地代码必须假设它可能不存在， 回退到 Canny + HoughLinesP。
  • 按角度分族，再对残差族求第二个水平消失点。 先分出竖直族与水平族，水平族求出第一个消失点后，把内点剔掉， 对剩下的线段再求一次 —— 这才是第二个水平族。
  • RANSAC 打分用长度加权，不要数内点个数。 一条 300 px 的桌沿和一条 40 px 的碎屑边缘对消失点的约束力差一个量级， 按个数计分会让一堆短噪声线压过真正的结构线。
  • 点到直线的容差要随长度自适应，不要用固定角度阈值： tol_px × max(1, len / 90)。长线段的端点定位误差会被外推放大， 给它更宽的容差反而更稳。
  • 最后在内点上做长度加权最小二乘精修。 RANSAC 只负责挑对集合，精度由精修给。
  • 焦距由两个正交消失点解出： f = sqrt( −[ (u₁−cx)(u₂−cx) + (v₁−cy)(v₂−cy) ] )。 括号内为正说明这两个方向在该主点下不可能正交，此路不通，别硬开根号。

出处提示：这几条来自本仓库两个消失点实现的并集。 分族后对残差族再求一次、受理窗口、多通道择优在 pipeline/core/calib_vp.py；长度加权打分、长度自适应容差 tol_px × max(1, len/90)、内点上的长度加权最小二乘精修在 recon/tools/calib.py。前者用的是固定角度容差 + 内点计数、且没有精修 —— 两版一比就知道后三条值得补。抄的时候抄并集。

受理窗口是必须的，不是可选的。
任何 hfov 落在 [30°, 120°] 之外的解一律拒收，并且把拒收原因记下来。 两个尾巴都真实发生过：同一张参考图上，一条实现解出 hfov = 15°（「越界弃用」），另一条实现解出 f = 113.28 px / hfov = 155.05°。 没有这道窗口的实现，会把 155° 当成答案照单全收， 然后整条管线在一个错到离谱的内参上继续往下算，而且不会报任何错。
配套两条：多个通道都给出可信解时互检，相差 > 15% 记一条 「可能非曼哈顿场景」；全部越界则退回先验 FOV，并把置信度打下去 —— 本仓库这张参考图上三条通道全部越界，自动解退回了 60° 先验， 最终生效的 95° 来自 fSpy 人工标定。

但 [30°,120°] 不是「合理镜头」的区间，它是「这套方法还成不成立」的区间。 这个区别决定了换项目时该怎么调它：

  • 上界卡的是针孔假设，不是视角。建筑与室内摄影 100–120° 很常见， 超广角与运动相机 120–150° 也是真实输入 —— 但到那个量级， 桶形畸变已经把直线掰弯，而整条消失点管线的输入就是直线。 所以正确的做法不是把上界抬到 150°，而是先做去畸变（或用畸变感知的 VP 拟合）， 去畸变之后再谈受理。做不了去畸变，那 120° 这个上界是诚实的： 再往上，解出来的 f 已经没有意义了。
  • 下界卡的是可观测性。长焦时两个消失点跑到画幅外很远， (u₁−cx)(u₂−cx)+(v₁−cy)(v₂−cy) 是两个大数相乘再相加， 条件数极差，几个像素的 VP 误差就能让 f 翻倍。 更贴切的判据是直接看这一项的条件数与 VP 内点残差，而不是看 hfov 落在哪。
  • 硬拒收带和软信任带应该是两条线。本管线其实就是这么做的，只是没写在一处： [30°,120°] 之外拒收，而 (35°,110°) 之外置信度直接 ×0.2 并记一条「疑似裁切图或畸变」。 人工覆盖走的又是第三条线 [20°,120°]（人可以输 25°，自动解不行）。 抄的时候把三条都抄走，只抄中间那条会失去大部分保护。

一点透视是头号失败模式

正对一面墙拍的室内图只有一个可信的水平消失点， 第二个水平族基本是伪的（它在无穷远，本就退化）。这时候：

  • 天顶消失点是救命通道 —— 竖直方向与任意水平方向正交， 所以「一个水平 VP + 天顶 VP」同样能解 f。
  • 但它的置信度必须打折。竖直线族的支撑天然更弱（数量少、跨度短、 容易被门框和管线污染）。本管线的做法是：解来自「两个水平 VP」记满权， 来自「含天顶 VP」的通道置信度直接 ×0.5。
  • 三对组合都算一遍，先用受理窗口筛掉不合理解，再按最弱一族的内点数择优。

相机高度：反解已知物高，锚点必须过滤

物体高度与相机高度严格成线性 H_obj = h · H₁， 所以 h = H_先验 / H₁，多个先验物取中位数抗离群。 这条路与焦距无关，把尺度和焦距解耦 —— 这是它的全部价值。 代价是锚点必须过滤，四条缺一不可：

  • 被画幅裁断的不要。它的「底边」是图像边界而不是着地点。 前景常有半截入画的椅子，用它反解会得到 9 cm 这种荒谬机位高。
  • 太小的框不要。一两像素的误差就能毁掉高宽比。本管线的下限是框高 12 px。
  • 只用落地物。桌上的东西反解出来的是「桌面到相机」，不是机位高。
  • 底边离地平线太近的不要。那里距离公式发散（下一节），留够像素余量再用。

解完还要一道常识钳制：一张室内照片的机位不可能是 9 cm 或 6 m。 越界说明锚点框或焦距不可信，钳回区间并判低置信，别让一个坏值污染整条管线。

离散度是你唯一能拿到的内部一致性检查

几个已知高度的物体各自反解出一个相机高，取它们的 MAD / median（中位绝对偏差 ÷ 中位数）。
它不能告诉你焦距、俯仰、机高三个量里错的是哪一个； 它能告诉你其中至少有一个错了。
没有这个量，一个自洽但完全错误的标定可以一路走到底而不被发现。

工程上把它接到两处：超过阈值（本管线 0.2）就在标定结果里记一条 note， 同时给总置信度乘一个惩罚系数（离散度 ≥ 0.15 时 ×0.4）。 另外每一次运行都把线段分族与地平线画成调试图落盘 —— 别做成「低置信才画」，因为你事后想复盘的那一次，当时的置信度往往并不低。

误差模型决定了下游每一个阈值

地面射线法的距离对底边像素的敏感度：

∂D/∂v ≈ D² / (f · h)
等价形式： D = h · f / margin        dD/dpx = h · f / margin²
margin = 物体底边到地平线的像素距离

这个式子的实际含义是：margin 是你能拿到的、最好的逐物体质量代理。 它不需要任何额外测量，纯几何量，而且和误差是解析关系。 所以它应该同时门控四件事：

  • 置信度 —— 本管线里它占最大权重（0.30，其余是「是否触画幅边」0.25、 「几何是否成立」0.20、「是否被钳」0.15、「三维盒是否印证」0.10）。
  • 高度锚点 —— 余量不足的不参与反解相机高。
  • 尺度尺子 —— 余量不足的实例高度不可信，不能当全局尺度校准的尺子。
  • 房间尺寸证据 —— 这条最容易被忽略，但后果最大。 房间盒是所有落地点的包围，一个病态解就能把整个房间撑大。 做法是给敏感度设一个上限（本管线 10 cm/px）：超过的物体照样摆放， 只是不作为「房间有多大」的证据。实测同一次运行里敏感度能跨 92 倍 （0.49 → 45.05 cm/px）—— 最远那个物体每读错一个像素就偏 45 厘米。

布局写在图像空间，不写坐标

每个实例记的是它与支撑面接触的那个像素 + 支撑面的名字， 由反投影解算成米。

{"id":"crt_L2", "asset":"M02", "support":"shelf_L",
 "anchor_px":[300,250], "yaw":88}

好处是可重导出：改相机、改房间尺寸、改搁板高度， 所有摆放会用同一台相机一致地重新推导，而不是各自漂移。 移动一个物体 = 改一个像素值，而这个像素值是你能在参考图上直接量到的东西。

解算器必须跑两遍：table:<id> 这种依赖已解算实例的支撑面， 第一遍拿不到宿主，第二遍才行。

射线打空支撑面时：重解，不要只钳

搁板只有一条窄带，射线经常落在带外。只把 x 钳回带内是错的 —— 那等于让物体沿着板子滑走，y（进深）还留在原来那条错误的射线上。正确做法：

xt = clamp(p.x, lo, hi)                    # 先把 x 钉到带边
q  = cam.unproject_plane(u, v, axis=0, xt) # 用 同一条射线 再与竖直平面 x = xt 求交
pos = [xt, q.y, shelf_z]                   # y 由重解得到，不是留用旧值

同样的逻辑用在桌面：先按桌面高度求交并钳进脚印， 如果原交点确实在脚印外，再用同一条射线与 y = 钳后的 y 平面重解 x。 钳制改的是约束，不是答案；答案要重新解一次。

尺寸的裁决权在先验，位置的裁决权在测量

尺寸看先验。FOV 只要有偏差，射线法解出的绝对尺寸就会系统性地偏大或偏小； 而「折叠椅约 80 cm 高」这件事的可信度远高于任何单张图上的测量。 所以对先验表里的类别：整体缩放因子取自实测高度与先验高度之比 （钳在 0.75–1.33 倍之间），三轴按先验比例重建；未知类别才原样用测量值。
位置看测量。位置没有先验可用 —— 没有任何常识能告诉你那台显示器在房间的哪个角落。

但这条会反过来，而且本仓库里已经反过来了。四种情形：

  • 类别内真实方差大时，先验会毁掉测量对的那部分。 本管线的先验表里有 table (140,70,75) 没有 long_table， 而类别归一是子串匹配 —— 于是一张 3 m 的长条桌被归到 table， 三轴按 140×70×75 重建，射线量对了的那个长度被先验抹掉。 判据很简单：先验只对「同一个名字意味着同一个尺寸」的类别有效 （折叠椅、门、A4 纸），对「同一个名字覆盖一个尺寸家族」的类别（桌、招牌、货架）无效。
  • 全局尺度已经用先验定过之后，就不该再逐物体用一次。 FOV 偏差造成的是全局的、乘性的误差，而这正是尺度校准那一步 （取先验物 先验高/实测高 的中位数）已经消掉的东西。 消完之后测量剩下的是相对信息 —— 这台显示器比那台大一圈 —— 而逐物体套先验会把它一起抹平。 更稳的切法是：先验定绝对尺度与长宽比，测量保留个体差异那一个自由度。
  • 先验表本身是场景类型的假设。「桌 75 cm」是办公/家居的常识； 工作台 90 cm、教室课桌 60–70 cm、实验台 85–95 cm。换场景类型要换表， 而不是换阈值。
  • 「位置看测量」同样会反 —— 只要接触点被遮挡或出画， 测到的锚点就是错的，这时候规则比测量强。本管线自己就在这么做： 射线落到支撑面脚印外时钳进脚印、物体解到房间外时拉回墙内 —— 这两处都是先验推翻测量。所以准确的说法是 「位置优先看测量，但测量必须先过可信度门（余量、是否触边），过不了就交给规则」， 而不是「位置永远看测量」。

全局尺度也是同一套：取已知先验物 (先验高 / 实测高) 的中位数作为尺度因子 s， |s−1| > 5% 就把相机高乘以 s 整体重解， 最多迭代三轮或直到 |s−1| ≤ 5%（人工标定过的相机不参与，那是真值）。 s 先钳进 [0.5, 2.0] 再用 —— 注意这是钳制不是弃用：越界时仍然会按边界值缩放， 所以必须同时记一条低置信，否则一批坏锚点照样能把整场尺度带走 0.5×。 当尺子的实例同样要过滤：触画幅边的、地平线余量不足的（< 8 px），一律不参与。

闭环只需要两件事

  1. 把解算结果重投影回参考图，和它自己的来源比。 房间线框画回照片，看后墙两角落在哪一列；物体框画回照片，看它压没压住原物。 这一步零成本，而且是唯一能证明「人工填的那个数是对的」的手段 —— 人工标定本身不是问题，人工标定给完直接用、一次都没投影回去核对才是。
  2. 验「渲染器」和「投影器」是否一致。 拿一格点阵（例如 5×4×3 = 60 个世界点），一边用你自己的投影函数算像素， 一边用 DCC 相机的实际投影算像素，逐点比对，超过阈值就报警。
    这是唯一能抓到全局系统性偏移的办法 —— 这类错误（yaw 符号约定不一致、主点偏移方向相反）在任何单帧里都完全看不出来： 没有一处「看着不对」，只是所有东西整体轻微错位。 符号约定不要靠推理，靠搜索：把几种约定都跑一遍，取误差最小的那个。

交互 · 深度灵敏度

通用公式，不带本项目数据。拖动三条滑块，看 D = h·f/margin 与 dD/dpx = h·f/margin² 在小余量处怎么炸开。曲线是 margin 从 2 px 扫到 200 px 的结果， 竖线是当前取值。

交互 · 受理窗口

拖两个消失点（直接拖图上的圆点，或用下面的滑块）， 实时算 f 与 hfov。越界时窗口变红， 并打印应该被记进 notes 的那一行 —— 记录理由和拒收本身一样重要， 否则下游只会看到一个莫名其妙的先验值。

画幅固定 1024×572，主点在中心。 f = sqrt(−[(u₁−cx)(u₂−cx)+(v₁−cy)(v₂−cy)])， hfov = 2·atan(W/2f)。括号内为正时无解 —— 这两个方向在该主点下不可能正交。
虚线圆是以 VP₁VP₂ 为直径的圆：主点落在圆内 ⇔ 有解， 而 f 正好是过主点那条垂直半弦的长度（括号里那一项就是主点对该圆的幂）。 把两个消失点拖近，圆缩小，主点跑到圆外 —— 无解看得见。

一页清单

压缩版，可以直接拿去对着执行。每一条在上文都有出处。

识别与分割（6 条）

  1. 先问场景、再问检测；把这张图自己的名词列表喂给检测器，不要用固定类别表。
  2. 至少三条召回：整图 + 语义热区 + 重叠分块；必要时加逐件枚举。同一份提示词，只换 crop。
  3. 分块时区分接缝与图边：碰人工切缝的丢，碰真实图边的留。这条不写，分块就是净负收益。 三个前提：轴对齐矩形裁块、重叠带宽于最大物体、留下的图边框必须带「被裁断」标记。
  4. 枚举先剔掉「几乎和父框一样大」的子框，剩下仍 ≥ 2 个才替换父框， 其余保留父框，一件不发明。
  5. 坐标序、归一化区间、退化框，全部在归一化层一次性吸收，下游只见标准形。
  6. 结构可靠性做成本地契约：去围栏 → 解析 → 配平扫描 → 校验 → 一次修复重试 → 写回缓存槽。 缓存键含模型/参数/提示词/图像字节，不含端点。

资产生成（7 条）

  1. 先按判据选路：要「这一件」走库匹配，要「这一类」走程序化。 比成本更该先看的是失败形态。
  2. 库资产必须离线预处理：保 UV 的减面、贴图降档、ORM 合并、坐标系与枢轴归一， 并落一份实测 stats.json。
  3. 字段所有权切分：语义字段人核过就冻结；几何字段永远从实测重写，人不改、模型不碰。
  4. 四级瀑布（人工 → 精确类别 → 视觉兜底 → proxy），同类变体按尺度无关的形状距离排序轮换。
  5. 畸形缩放保护取三轴比中位数；放大钳、缩小不钳；屏幕类锁长宽比； 10 倍级差异判误匹配，换下一个候选。阈值要从你自己库的比值分布里定 —— 1.7 / 10 / 0.1 只在「库网格已是真实尺寸」时成立，归一化的库要先缩到位再套。
  6. 「未知」和「细长线缆」两类禁止进库匹配；平面印刷品走贴花， 贴花源用白底预览渲染而不是基础色图集。
  7. 程序化侧：一份总平面两处消费、颜色进顶点色、噪声按周期取模保平铺、 每格自带种子、按材质桶合并、LOD 做在生成层。

相机与位姿（10 条）

  1. 骨架只有「像素 → 射线 → 与声明的支撑面求交 → 米」。换 DCC 不改这一层； 改的是搬运层，而搬运层有六件事：手性、单位、上轴、枢轴、欧拉序与旋转正方向、 FOV 沿哪根轴。只换前两件是最常见的翻车法。
  2. 按 attached_to 拓扑排序分层求解：地面物 → 房间盒 → 支撑面物 → 墙/顶物；环依赖降级为落地物。
  3. 消失点：CLAHE + LSD（带 Hough 回退）、分族后对残差族再求一次、 长度加权打分、长度自适应容差、内点上长度加权最小二乘精修。
  4. 设受理窗口并记录拒收理由。hfov 出 [30°,120°] 一律弃用， 出 (35°,110°) 置信度打到两成。这个窗口卡的是针孔+消失点这套方法还成不成立， 不是镜头合不合理 —— 真要处理 120°+ 的超广角，先做去畸变，别抬上界。
  5. 一点透视用天顶 VP 救，但把它的置信度打折；多通道解相差 > 15% 记一条「可能非曼哈顿」。
  6. 机高由已知物高反解、取中位数；锚点过滤四条：不裁断、不太小、只落地、地平线余量够。 解完加常识钳制，并把越界记成低置信。
  7. 用 MAD/median 离散度做内部一致性检查 —— 它指不出谁错，但能证明有人错了。
  8. 拿 margin 当逐物体质量代理，同时门控置信度、高度锚点、尺度尺子、房间证据。 射线打空支撑面时重解，不要只钳。
  9. 尺寸看先验、位置看测量，但两边都有反向条件：先验只对「同名即同尺寸」的类别 有效（长桌、招牌这类尺寸家族会被先验抹平），且全局尺度已用先验定过之后不该再逐物体套一次； 测量过不了可信度门（余量、触边）时位置也要交回规则。
  10. 闭环两件事：解算结果重投影回参考图比对；点阵双向投影验渲染器与投影器一致 —— 后者是唯一能抓到全局系统性偏移的手段，也是上面那张「六件事」转换表的验收测试。
如果只能记一条：语义走模型，几何走算法，模型的几何输出只当提示。 这条线上每一次返工，事后追溯都是它被打破的那一次。

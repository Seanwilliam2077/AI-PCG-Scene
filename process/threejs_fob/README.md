# FOB Site — 程序化前进作战基地 (three.js)

> **归档说明**：这是仓库「并行线二」的完整可运行源码，原开发位置在另一个仓库的 `webui/base3d/`，此处按原样归档，仅把 README 里的路径改成本仓库内的位置。
> 设计推理与八轮迭代记录见 [`docs/对照实验-程序化场景重建.html`](../../docs/对照实验-程序化场景重建.html)。

浏览器里实时渲染的沙漠军事基地。**没有任何外部模型或贴图文件** —— 所有几何、
所有贴图（混凝土、波纹铁皮、帆布、锈蚀金属、木板、HESCO 填料、沙地、铁丝网）
都是页面加载时用 JS 和 Canvas 2D 现算出来的。给一个种子，出一个基地。

## 跑起来

```bash
python process/threejs_fob/serve.py 8177
```

然后打开 <http://127.0.0.1:8177>。

> Windows 上不要用 `python -m http.server`：它从注册表读 MIME 映射，
> `.js` 常被解析成 `text/plain`，浏览器会拒绝加载 ES module。
> `serve.py` 把 MIME 表写死了。

依赖只有 three.js 本体：

```bash
cd process/threejs_fob && npm i
```

## 怎么组织的

```
src/
  rng.js        可复现的伪随机源（mulberry32 + range/pick/weighted/…）
  textures.js   全部程序化贴图 + 材质定义 + 环境球
  builder.js    带变换栈的几何累加器，按材质分桶最后 merge
  layout.js     总平面：院落网格、道路、周界、岗楼位置
  ground.js     把总平面烘进一张 4096² 地面贴图，并生成起伏网格
  props.js      场站构件库（墙、网、岗楼、天线、桅杆、集装箱、桶、灯杆…）
  buildings.js  建筑生成器
  vehicles.js   载具与直升机
  base.js       按 layout 把上面这些摆出来
  main.js       渲染器 / 光照 / 后期 / UI
```

两个设计决定值得说一下：

**一切进同一个变换栈，按材质分桶合并。** 四万多个构件最后只剩 13 个 Mesh —— 每种
材质一个。颜色变化全部走顶点色，所以同一个 `concrete` 材质能同时当墙、楼、
掩体和路缘石。发射几何时顺手按世界高度烘一层接地暗部，物体才"坐"得住。

**地面是烘出来的，不是拼出来的。** 场坪、道路、轮胎印、油渍、停机坪标线、
分仓缝、裂缝全部画进一张 4096² 贴图（一个 draw call），高频细节交给一张小尺寸
平铺法线。因为烘焙和摆放读的是同一份 `layout` 数据，混凝土场坪永远和院墙对得上。

## 面板

- **种子** —— 换一个数字就是另一个基地；同一个数字永远给出同一个基地
- **相机** —— `原图` 是对着参考图调的机位；还有俯视和地面视角
- **光照** —— 太阳方位 / 高度、曝光、沙尘浓度
- **画质** —— GTAO 环境光遮蔽、阴影、调色/暗角/颗粒开关

## 性能

1280×720、GTAO 全开，约 24 ms/帧（1.7 M 顶点，60 余次绘制调用，含阴影和 AO 的
额外 pass）。嫌卡就关掉 GTAO。换种子重建整个基地约 4 秒。

## 调试

`window.__fob` 暴露了 `scene / camera / renderer / composer / generate() / info`，
以及 `shoot(name, w, h)` —— 把当前画面 POST 到 `serve.py` 存进 `_shots/`，
用于无法截屏的无头环境。
